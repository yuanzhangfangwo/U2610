# U2610 代码与协作规范

本文件规定脚本怎么写、程序集怎么分、提交怎么写。资源放哪、怎么命名见 `资源管理约定.md`。对应的 Cursor 规则在仓库根目录 `.cursor/rules/`，AI 写代码时自动遵守。

## 脚本文件头与注释

每个新建脚本在 `using` 之前写文件头：

```csharp
// ============================================================
// 创作者：yuanzhangfangwo
// 创作时间：2026-10-17 17:20
// 主要功能：处理玩家冲刺的位移与冷却。
// 主要 API：
//   TryDash(Vector3 direction) —— 尝试朝指定方向冲刺，冷却中返回 false
// ============================================================
```

- 创作者填自己的 `git config user.name`，创作时间格式 `yyyy-MM-dd HH:mm`。
- 修改别人的脚本不改创作者和时间；公开 API 有增删时同步更新“主要 API”。
- 每个函数上方用 `/// <summary>` 写明用途，有参数或返回值时补 `<param>`、`<returns>`。
- 函数内的局部变量在函数开头统一声明，再写逻辑。循环变量和 `out var` 例外。

## 编码与风格

`U2610/.editorconfig` 固定了编码与格式，Rider 和 Visual Studio 会自动读取：UTF-8、4 空格缩进、`.cs` 用 CRLF 换行。中文注释必须是 UTF-8，否则另一台电脑打开会乱码。

- 一个文件一个公开类型，文件名与类型名一致，类型名用英文 PascalCase。
- 公开成员 PascalCase；私有字段、参数、局部变量 camelCase，不加下划线前缀。
- 需要在 Inspector 调整的字段写 `[SerializeField] private`，对外读取用只读属性。

## 程序集与命名空间

| 目录 | 程序集 | 可以引用 |
| --- | --- | --- |
| `Scripts/Tool/` | `U2610.Tool` | 只用 Unity 引擎 |
| `Scripts/Server/` | `U2610.Server` | `U2610.Tool` |
| `Scripts/Client/` | `U2610.Client` | `U2610.Tool`、Input System、UGUI、TextMeshPro |
| `Scripts/Editor/` | `U2610.Editor` | 以上全部，只在编辑器编译 |

- 命名空间与目录对应，例如 `Scripts/Client/Combat/` 用 `U2610.Client.Combat`。
- `Client` 与 `Server` 不互相引用，需要共用的接口、事件、数据结构放 `Tool`。
- 新增第三方包时，只在需要它的程序集里加引用。
- `Scripts/` 根目录的脚本会落进 Unity 默认程序集，上面四个程序集都引用不到它，所以根目录不放脚本。

## 禁止魔法数字

- 逻辑里不写无名数字或字符串。计数、索引用的 `0`、`1`、`-1` 例外。
- 会调整的数值（速度、伤害、前后摇、冷却）放 `Assets/Data/` 的 ScriptableObject。
- 固定值写成 `const` 或 `static readonly`。
- Tag、Layer、场景名、Animator 参数集中写在 `U2610.Tool` 的常量类里，Animator 参数用 `Animator.StringToHash` 缓存。

## Unity 脚本写法

- 组件引用在 `Awake` 里取一次存进字段，或在 Inspector 拖拽。`Update` 类函数里不调用 `GetComponent`、`Find` 系列，也不 `new` 引用类型。
- 不用 `SendMessage`、`BroadcastMessage`。
- `Awake` 初始化自身，`Start` 再访问其他对象。
- 事件在 `OnEnable` 订阅、`OnDisable` 注销，成对出现。
- 刚体速度与受力放 `FixedUpdate`。顿帧、暂停期间仍要走的计时用 `Time.unscaledDeltaTime`。
- 射线与重叠检测必须带 LayerMask。
- 输入只用 Input System 包，不用旧版 `Input.GetKey` 等接口。读取输入放在 `U2610.Client`，角色逻辑不直接读设备。

## Git 提交与分支

提交信息格式 `类型: 简述`，简述用中文：

| 类型 | 用途 |
| --- | --- |
| `feat` | 新功能或玩法 |
| `fix` | 修复问题 |
| `art` | 美术、动画、音频 |
| `refactor` | 不改变行为的代码调整 |
| `data` | 数值与配置 |
| `docs` | 文档与 Cursor 规则 |
| `chore` | 工程设置、包、构建 |

- 一次提交只做一件事。资源与 `.meta` 同一次提交。提交前 Console 无编译错误。
- `main` 始终能打开、能进游戏。功能分支 `feature/player-dash`，修复分支 `fix/block-turn`。
- 合并前先拉最新 `main`，在编辑器里跑一遍相关场景。
- 场景或共享预制体冲突时不手拼 YAML，保留一方版本，另一方重做改动。
