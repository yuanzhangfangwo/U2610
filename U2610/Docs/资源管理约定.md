# U2610 资源管理约定

Unity 工程在仓库的 `U2610/` 目录。这是两人协作的单机项目，本约定只规定资源放哪、怎么命名、什么进 Git。

## 仓库边界

提交这些内容：

- `Assets/`（含全部 `.meta`）
- `Packages/`
- `ProjectSettings/`
- `Docs/`
- 工程内的 `.gitignore`、`.editorconfig`，以及仓库根目录的 `.gitattributes`、`.cursor/rules/`

不提交 Unity 本机生成物：`Library/`、`Temp/`、`Obj/`、`Logs/`、`UserSettings/`、`Build/`、`Builds/`，以及 `*.csproj`、`*.sln`。

`.meta` 和对应资源必须同一次提交。删资源时连同 `.meta` 一起删。贴图、模型、音频、视频走仓库根目录已有的 Git LFS 规则。

## 目录

新资源按这个结构放。`Settings/` 已存在，只放 URP 管线资源，不放游戏配置。

```text
Assets/
  Art/            模型、贴图、材质
    Characters/
    Environment/
    VFX/
    UI/
  Animations/     动画片段、Animator
  Audio/
    BGM/
    SFX/
  Data/           ScriptableObject 配置
  Input/          Input Actions
  Prefabs/
    Characters/
    Combat/
    Environment/
    UI/
  Scenes/
  Scripts/
    Client/       客户端：角色、战斗表现、输入、界面
    Server/       服务器端逻辑
    Tool/         通用工具类，客户端与服务器端都可引用
    Editor/       只在编辑器运行的脚本
  ThirdParty/     无法用 Package Manager 安装的第三方资源
```

`Assets/Settings/` 保持管线专用。模板自带的 `Assets/TutorialInfo/` 和 `Assets/Readme.asset` 是 URP 欢迎页，不参与游戏，确认不用后整份删除。

`Scripts/` 下按职责分到 `Client/`、`Server/`、`Tool/`、`Editor/`，各自内部再按功能建子目录，例如 `Client/Combat/`。四个目录各有一个程序集定义（`U2610.Client`、`U2610.Server`、`U2610.Tool`、`U2610.Editor`），引用方向由编译器检查，详见 `Docs/代码与协作规范.md`。`Scripts/` 根目录不放脚本。

不要新建 `Assets/Resources/` 来堆关卡或角色。常驻的少量引用可以直接序列化在场景或预制体上；内容变多后再单独引入 Addressables。

## 命名

文件夹和资源文件用英文 PascalCase。脚本文件名与类名一致。

| 种类 | 格式 | 示例 |
| --- | --- | --- |
| 场景 | `SC_名称` | `SC_Boot` |
| 预制体 | `PF_名称` | `PF_Player` |
| 材质 | `M_名称` | `M_PlayerBody` |
| 贴图 | `T_名称` | `T_PlayerBody` |
| 动画片段 | `A_对象_动作` | `A_Player_Dash` |
| Animator | `AC_对象` | `AC_Player` |
| 配置 | `SO_名称` | `SO_PlayerMove` |
| 音效 / 音乐 | `SFX_` / `BGM_` | `SFX_Hit`、`BGM_Stage` |
| 脚本 | 与类名相同 | `PlayerMotor.cs` |

同一资源的贴图、材质、动画放在该资源自己的子目录里，例如 `Art/Characters/Player/`。不要在 `Art/` 根目录堆文件。

## 场景、预制体与数据

场景只负责拼装和引用，可玩内容放进预制体。角色、敌人、打击判定、界面块各自成预制体后再拖进场景。

会反复调整的数值放 `Assets/Data/` 的 ScriptableObject，不写死在场景或组件默认值里。例如移动速度、攻击前后摇、冲刺距离。

`Assets/InputSystem_Actions.inputactions` 是模板留下的输入资源。新增或改动作时把它移到 `Assets/Input/`，并保持 `.meta` 一起移动，避免引用丢失。

## 两人协作

同一时间只有一个人改同一个 `.unity` 或被多人引用的预制体。需要并行时，把内容拆成不同预制体，各自改各自的文件。

第三方包优先用 Package Manager。必须放进工程时放 `Assets/ThirdParty/`，不改其中的源码；要改就复制出来放到 `Assets/Scripts/`。

## 提交前检查

- 新文件都在上表对应目录里，命名符合前缀。
- `.meta` 已一并加入。
- 没有带上 `Library/`、`Logs/`、`UserSettings/`。
- 场景里没有只存在于本机的绝对路径或缺失引用。
